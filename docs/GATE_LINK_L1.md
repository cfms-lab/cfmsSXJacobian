# 엔진 연결 L1 — 엔진용 생성 변형 `EvalEngine*` (노드쌍 J · V 블록)

판정 기준은 실행 전에 고정한다(볼트 규칙 §1, 2026-11-13). 계획은 `docs/PLAN_ENGINE_LINK.md` 의 L1 이다.
**결과(2026-11-13): L1-0 – L1-3 모두 PASS.** 뒤에 더한 L1-4(감쇠 없는 GN)도 PASS. 명세 다섯 · 판 열하나에서 노드쌍 블록 · 행 합 복원 · 전역 곱이 모두 반올림
수준(최대 2.6e-13)으로 맞는다. 보고: 전치 처리를 끄면 굽힘 셋과 Baraff–Witkin 전단은 전역 곱이 3 – 63 % 틀린다. 블록이 대칭인
인장만 끈 채로 맞다. 아래 「결과」.

## 왜

이 리포의 `EvalImplicit*` 는 원문 식 (6) 의 요소 기여 `A_e = −h ∂f/∂v − h² ∂f/∂x`(위 삼각)와 `b_e` 를 낸다. 엔진(cfmsDrape
CPU, 378d20c)은 이것을 받지 못한다. 엔진이 받는 것은 다음과 같다(엔진 소스를 읽어 확인, 아래 「엔진 규약」).

- 힘 `f + d`.
- **노드쌍 블록 둘**: `J = ∂f/∂x` 와 `V = ∂f/∂v`. 노드쌍마다 3 × 3 블록 하나씩이고, 대각 블록은 저장하지 않는다.
- 선형계는 엔진이 만든다: `A = M − h V − h² J`, `b = h (f + d) + h² J v`.

그래서 생성기가 엔진 꼴의 변형을 하나 더 낸다. 강성 판(정확 · GN · T)은 기존 변형과 같은 계수 바꾸기로 고른다.

## 엔진 규약 (cfmsDrape_dev 378d20c, 읽어 확인 2026-11-13)

- **곱 연산** `SDEPCGSolver::_Jacobian_VectorProduct`(`SDESparseMatrix.cpp:4142-4308`). 저장된 블록 `B`(행 노드 i, 열 노드 j)마다
  `out_i += B (v_j − v_i)` 와 `out_j −= B' (v_j − v_i)` 를 한다. `B'` 는 전치 처리 플래그가 켜지면 `Bᵀ`, 꺼지면 `B` 다.
  - 이것이 나타내는 전역 행렬은 `J_ij = B`, `J_ji = B'`, 대각 `J_ii −= B`, `J_jj −= B'` 이다. 곧 **대각 블록 = −(그 행의 이웃 블록 합)**
    (행 합 규약)이다. 병진 불변인 힘에서만 맞는 규약이다.
  - 전역 행렬이 대칭이려면 `B' = Bᵀ` 여야 한다. 그래서 블록이 비대칭이면 플래그를 켜야 한다.
- **전치 처리 플래그** `bUseTransposeAwareUpperJacobian` 의 기본은 꺼짐이다(`SDESparseMatrix.cpp:1266`). 켜는 곳은 둘뿐이다 —
  비선형 전단 다항식(`SDEVC.cpp:909`)과 굽힘 감쇠 암시 모드(`SDEVC.cpp:1394`, `SDECore.cpp:8077`).
  - 엔진 인장은 블록이 대칭이라 꺼진 채로 맞다. 블록이 `a d_a d_b ŵŵᵀ` · `(I − ŵŵᵀ)` 꼴이기 때문이다.
  - 이 리포의 굽힘 · Baraff–Witkin 전단 블록 `∇_a C ∇_b Cᵀ` 는 비대칭이다. 그래서 엔진 갈래(L2 · L3)는 플래그를 켜야 한다.
- **인장 커널**(`SDECore.cpp:9324-9660`)은 삼각형마다 지역 쌍 (0,1) · (0,2) · (1,2) 의 블록만 낸다(`N0 = {1, 2, 3}`).
  `J` 블록은 `−k Σ ∇C∇Cᵀ − k Σ C⁺ ∇²C − kv Σ Ċ⁺ ∇²C` 이고(`bPositiveDefiniteOnly`), `V` 블록은 `−kv Σ ∇C∇Cᵀ` 다.
- 조사 보고(같은 날)의 「J · V 를 따로, 노드쌍 블록만」 을 위 두 곳에서 다시 읽어 확인했다. 엔진이 실제로 이렇게 도는지는 L0
  (`docs/GATE_LINK_L0.md`)가 잰다.

## 변형의 정의

성분 c 마다 `s_c = k C_c + kd Ċ_c`, `Ċ_c = ∇C_c · v`, `C⁺ = max(C, 0)`. 요소 행렬은 모두 대칭이다(감쇠의 비대칭 항
`∇C (∇²C v)ᵀ` 는 기존 변형처럼 버린다).

| | `EvalEngine` (정확) | `EvalEngineGN` | `EvalEngineTension` |
|---|---|---|---|
| 힘 `f + d` | `−Σ s_c ∇C_c` | 같다 | 같다 |
| `J` | `−k Σ ∇C∇Cᵀ − Σ s_c ∇²C_c` | `−k Σ ∇C∇Cᵀ` | `−k Σ ∇C∇Cᵀ − k Σ C_c⁺ ∇²C_c` |
| `V` | `−kd Σ ∇C∇Cᵀ` | 같다 | 같다 |
| 짝이 되는 기존 변형 | `EvalImplicit` | `EvalImplicitGN` | `EvalImplicitTension` |

- **세 판 모두 `A_e = −h V − h² J`, `b_e = h (f + d) + h² J v` 이다.** 엔진 식에 넣으면 짝이 되는 기존 변형의 `A` · `b` 가 된다.
  정확판은 `h(f + d) + h²Jv = −Σ h k C ∇C − (h kd + h² k) Σ Ċ ∇C − h² Σ s ∇²C v = −Σ h k C ∇C − A v` 로 확인된다.
  나머지 둘도 같은 방식으로 확인된다.
- **입출력.** `EvalEngine*(x, ev, v, prm, C, f, J, V)`. `prm = {k, kd}` 이고 h 는 받지 않는다(엔진이 곱 안에서 곱한다).
  - 출력: `C[kComp]`, `f[kDof]` = `f + d`, `J[9 kPairs]`, `V[9 kPairs]`.
  - 노드쌍 p 는 지역 꼭짓점 `(a, b)`, `a < b`, 사전순이다. 삼각형은 3 쌍, 힌지는 6 쌍이다.
  - 블록은 행 우선이다: `J[9p + 3i + j] = J_{3a+i, 3b+j}`(`∂f_a/∂x_b` 의 (i, j) 성분).
  - **대각 블록은 내지 않는다** — 행 합 규약으로 정해진다.
- **따로 된 헤더.** 엔진 변형은 `generated/<이름>_Engine.h`(`struct <이름>Engine`)에 쓴다. 엔진 갈래에는 이 헤더만 복사하면 된다.
  하네스 헤더 `generated/<이름>.h` 는 바이트까지 그대로다.
- **생성기 코드.** 기존 `emit_staged` 는 고치지 않는다. 같은 단계판 유도(`derive_staged`)를 읽는 새 함수 `emit_engine` 을 둔다.
  - 블록의 `∇C∇Cᵀ` 몫은 좌표 공간의 `g = Jᵀ ∇ᵤC` 로 한 번 만들어 `J` · `V` 가 함께 쓴다.
  - `∇²C` 몫은 기존 변형처럼 중간 변수 공간에서 이어 계산한다(`Jᵀ (β ∇²ᵤC) J + Σ β ∂C/∂uₖ ∇²ₓuₖ`).
- 어떤 명세가 어떤 판을 내나: 단계판이 있는 명세 다섯 모두 `EvalEngine` · `EvalEngineGN` 을 낸다. `IMPLICIT_TENSION = True`
  인 명세(지금은 인장만)는 `EvalEngineTension` 도 낸다.

## 명제 — 기준은 실행 전에 고정

표본은 Gauss–Newton 게이트와 같다. 힌지 1000 개(`results/hinges.txt`)로 Baraff 굽힘 · 압축 명세 · Bridson 굽힘을 보고,
삼각형 1000 개(`results/triangles.txt`)로 인장 · 전단을 본다. 스텐실 값은 N1 과 같다: Baraff 둘은 θ0, Bridson 은 그 표본의
`w̄ = 3|e|² / (½|nA| + ½|nB|)`, 삼각형은 쉬는 uv 다. 계수는 k = 1, kd = 0.1, h = 0.01(N1 과 같음)이다. 상대 오차의 척도는
명제마다 아래에 적었다.

| 명제 | 내용 | 기준 |
|---|---|---|
| L1-0 전제 — 기존 출력 불변 | 하네스 헤더 다섯의 SHA-256 이 아래 「기준값」과 같다. `results/codegen_*.json` 의 기존 변형(`exact` · `frozen` · `staged` · `implicit` · `implicit_gn` · 인장의 `implicit_tension`) `body_sha256` 이 55c9745 의 것과 같다. 엔진 헤더 다섯이 있고, `engine` · `engine_gn` 은 다섯 모두, `engine_tension` 은 인장에만 있다 | 모두 같음 |
| L1-1 정의 | 명세 · 판마다 생성 블록을 기준과 견준다. 기준은 평탄판 `Eval` 의 C · ∇C · ∇²C 로 만든 요소 행렬이다: 정확판은 `AssembleConditionForce` 의 `K + ∂d/∂x`(비대칭 항 버림)와 `∂d/∂v`, GN 은 같은 함수에 ∇²C = 0, T 는 `−k Σ(∇C∇Cᵀ + C⁺∇²C)` 를 손으로 조립. J · V 블록 오차는 기준 요소 행렬 전체(대각 포함)의 최대 크기로 나눈다. f + d 는 기준 f + d 의 최대 크기로 나눈다. C 는 N1 의 척도(굽힘 1, Bridson `√w̄`, 삼각형 `√a`)로 나눈다 | 각 1e-12 이하 |
| L1-2 행 합 복원 | 블록과 행 합 규약으로 요소 행렬 `J_full` · `V_full` 을 되살린다(`(b, a)` = `(a, b)ᵀ`, 대각 = −행의 이웃 합). 그 뒤 `A_rec = −h V_full − h² J_full`(위 삼각), `b_rec = h f + h² J_full v` 를 짝이 되는 기존 변형의 A · b 와 견준다. A 는 A 의 최대 크기로 나눈다. b 는 `max(|b|, |h f|)` 의 최대 크기로 나눈다 — b 는 `h f` 와 `h² J v` 가 서로 지우는 합이라, 더한 항의 크기를 척도로 둔다 | 각 1e-12 이하 |
| L1-3 전역 곱 | 격자 천(`MakeGrid`, G = 12, 노드 144, 삼각형 242, 힌지 341)을 쓴다. 쉬는 uv 는 평평한 격자(간격 1 cm), θ0 = 0, Bridson w̄ 은 그 상태의 값, v 는 격자 속도다. 요소 블록을 노드쌍 슬롯에 모은다: 전역 번호가 `ga < gb` 면 `(ga, gb)` 슬롯에 `J_ab`, 아니면 `(gb, ga)` 슬롯에 `J_abᵀ` 를 더한다. 그 슬롯으로 위 「엔진 규약」의 곱 연산을 **전치 처리 켬**으로 흉내 낸다. 그 결과를 기준 요소 행렬(L1-1 의 기준, 대각 포함)을 직접 곱해 흩뿌린 값과 견준다. 무작위 벡터 3 개, J 와 V 각각, 기준 곱의 최대 크기로 나눈다 | 각 1e-12 이하 |
| L1-4 감쇠 없는 GN (2026-11-13 추가, `docs/GATE_LINK_L4.md` 「2 차 (다)」) | 명세 다섯의 표본(위와 같음)마다 k = 1 · 3.7 에서 `EvalEngineGNUndamped(x, [ev], {k})` 의 C · f · J 가 `EvalEngineGN(x, [ev], v = 0, {k, 0})` 의 C · f · J 와 같다(`==` 로 견준다 — −0 과 +0 은 같게, NaN 은 다르게 센다). 엔진 굽힘 갈래가 감쇠 없이 돌 때 이 변형을 부른다 | 다른 표본 0 |

L1-0 덧붙임(2026-11-13, 위 L1-4 와 함께): 엔진 헤더 다섯에 `engine_gn_undamped` 가 기존 엔진 변형 뒤에 더해진다. 기존 엔진 변형(`engine` · `engine_gn` · 인장의 `engine_tension`)의 `body_sha256` 은 그 변형을 더하기 전 커밋 df547d8 의 것과 같아야 한다(`tests/check_link_l1_p0.py`). 하네스 헤더 다섯의 SHA-256 은 위 기준값 그대로다.

보고(판정 밖):

- L1-3 을 전치 처리 **끔**으로 흉내 냈을 때의 오차. 블록이 대칭인 명세에서만 작아야 한다 — 끄면 안 되는 명세가 어느 것인지 보인다.
- 엔진 변형의 연산 수 · 임시 값 수를 짝이 되는 `EvalImplicit*` 와 견준다(`results/codegen_*.json`). 시간은 L6 에서 잰다 —
  한 exe 의 시간은 로드 주소 함정(`docs/GATE_SPEED.md`) 때문에 판정에 쓰지 않는다.
- T 판의 갈래 수(인장 성분 C > 0 · C ≤ 0)를 적는다. 표본이 인장 판 게이트 P1 과 같으므로 같은 수가 나와야 한다.

### L1-5 와 Provot 전단으로 넓힘 (2026-11-13 추가, 기준은 실행 전에 고정 — 엔진 연결 L3 의 준비)

엔진의 인장 · 전단 손 코드는 J 에 감쇠의 기하 몫을 더 넣는다 — 성분마다 `Ċ > 0` 일 때 `−kd Ċ ∇²C`(인장
`SDECore.cpp:9609-9637`, 전단 `_GetImplicitShear_Provot_WithInvariant`). 이 리포의 T 판은 `∂d/∂x` 를 버린다. 사용자 결정
(2026-11-13): 엔진과 같게 그 몫을 넣은 엔진 꼴 변형을 생성기에 더한다. 그러면 생성 갈래가 엔진 손 코드와 모든 상태에서 맞는다.

- 새 변형 **`EvalEngineTensionRate`**(json 키 `engine_tension_rate`) — `IMPLICIT_TENSION = True` 인 명세(인장 · Provot 전단)의
  엔진 헤더에만, 기존 엔진 변형 뒤에 낸다. `J = −k Σ ∇C∇Cᵀ − Σ (k max(C, 0) + kd max(Ċ, 0)) ∇²C`. C · f + d · V 는
  `EvalEngineTension` 과 같은 식이다. 하네스 헤더에는 짝(`EvalImplicit*`)을 내지 않는다 — 이 리포의 적분 판정에 쓰는 판이 아니다.
- Provot 전단 명세(`ProvotShear`, `docs/GATE_PROVOT_SHEAR.md`)를 L1 의 여섯째 명세로 넣는다. 표본은 그 게이트와 같다
  (`results/triangles.txt` + `results/provot_diag.txt`), 격자는 인장과 같은 격자에 대각선 길이 √2 √2.

| 기준 | 무엇 | 통과 |
|---|---|---|
| L1-0 덧붙임 | 하네스 헤더 다섯과 기존 변형의 해시가 그대로다. 기존 엔진 변형의 `body_sha256` 이 이 변형을 더하기 전 커밋(816a73d)과 같다. `engine_tension_rate` 는 인장에만 있다(다섯 가운데) | 모두 같음 |

L1-2(행 합 복원 대 `EvalImplicit*`)는 짝이 없어 `EvalEngineTensionRate` 에는 하지 않는다. 행 합 규약은 L1-3 꼴의 전역 곱이 본다.

**결과(2026-11-13): 모두 PASS** — `results/gate_link_l1.json`(명세 여섯 · 판 열여섯).

- L1-0: 하네스 헤더 다섯 · 기존 변형 · 기존 엔진 변형(`engine_gn_undamped` 포함)의 해시가 그대로다. `engine_tension_rate` 는
  다섯 가운데 인장에만 있다. 엔진의 Bridson 헤더 사본도 그대로다(SHA-256 3bc0dcd8…).

  b 1.3e-14 이하, L1-3 전역 곱 3.8e-16 이하. L1-4 다른 표본 0 / 2000.
- L1-5 `EvalEngineTensionRate`: 인장 J 9.0e-16 · V 8.7e-16 · f + d 8.3e-15 · 전역 곱 4.7e-16, Provot 전단 J 1.3e-15 · V 6.6e-16 ·
