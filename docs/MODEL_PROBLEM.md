# 착수 게이트 — Baraff 굽힘을 명세 한 줄에서 자동 유도한다

볼트 규칙 `Rules/SFTF_PFTF_새응용프로젝트_추가방법.md` §1 에 따라 **판정 기준을 실행 전에 고정**하고
최소 문제(힌지 하나 = 꼭짓점 4개 · 자유도 12)로 판정한다. 엔진에는 붙이지 않는다.

## 왜 굽힘부터인가

Baraff & Witkin (1998) §4.3 의 굽힘 조건은 `C = θ`, `sin θ = (n̂₁ × n̂₂)·ê`, `cos θ = n̂₁·n̂₂` 이다.
원문은 미분을 손으로 감당하려고 **"n₁, n₂, e 의 길이를 상수로 본다"** 고 적는다. 이 구조의 힘 · Jacobian
가운데 손 유도가 가장 어렵고(IJ-2018-818 에서도 시간 대부분이 굽힘 항), 엔진의 손 코드
(`cfmsDrape_dev/drape/src/sde_core/SDECore.cpp` `CheckBendingChange_Macri_SOA`)도 SoA 배열과 SSE 매크로로
수백 줄이다. 가장 어려운 것이 되면 나머지(인장 · 전단)는 같은 길로 된다.

## 명제

| | 명제 |
|---|---|
| P1 | 사용자가 조건 함수 한 줄(`codegen/specs/baraff_bend.py`)만 쓰면 생성기가 `C`, `∇C`(12), `∇²C`(12×12)를 **정확히** 낸다 |
| P2 | 같은 `C · ∇C · ∇²C` 로 조립한 감쇠 Jacobian `∂d/∂x`(비대칭 항 포함)가 맞다. 원 논문이 버린 비대칭 항 `∇C (∇²C v)ᵀ` 의 크기를 잴 수 있다 |
| P3 | 원문 §4.3 의 길이 고정 가정을 같은 명세에 기계적으로 적용한 미분(`EvalFrozen`)이 정확한 미분과 얼마나 다른지 잰다 |
| P4 | 명세의 변수 선언에서 SXMesh 변수를 이름으로 만들고, 스텐실 루프가 그 배열(변수 단위 SoA)에서 모아 같은 값을 낸다 |
| P5 | 생성 코드의 힌지당 시간 — **이번 게이트에서는 재기만 하고 판정하지 않는다.** 엔진 손 코드와 같은 힌지 집합으로 비교하는 것이 다음 게이트다 |

> [!warning] 엔진 손 코드는 정확도 기준이 아니다 (사용자, 2026-11-12)
> `GetImpBending_Oh_SOA`(Bridson 굽힘)는 손으로 짠 코드라 **정확하다고 볼 수 없다.** 엔진 손 코드와는 **속도만**
> 비교한다. 정확도 기준은 독립 CAS(Mathematica)와 유한차분이다. 거꾸로, Bridson 굽힘을 명세로 쓰면
> 자동 유도판이 그 손 코드의 오차를 재는 기준이 된다(후속 게이트 후보).
> Baraff 경로의 `CheckBendingChange_Macri_SOA` 는 Macri 의 소스를 고친 것이라 오류가 적을 것이다(사용자 기억).
> 값을 견줄 상대로는 쓰지만 기준은 아니다.

### 보고 항목 (판정 없음)

**P3 길이 고정 근사.** `C` 는 같고, `∇C` 상대오차 중앙 17 % · 최대 57 %, `∇²C` 중앙 32 % · 최대 101 %.
`∇C` 의 차이는 **전부 공유 변 방향의 한 항**이다:

```
g_frozen − g_exact = cosθ·sinθ / |e| · ê   (x_j 에 +, x_i 에 −, x_h · x_k 에는 0)
```

1000 힌지 모두에서 이 식과 반올림(8e-16)까지 같다(검산 프로그램은 리포 밖 일회용). 이유: `∂θ/∂n̂ ⟂ n̂` 이라
노멀 길이 고정은 기울기를 바꾸지 않고, `∂θ/∂ê = cosθ·sinθ·ê ∥ ê` 라 변 길이 고정만 바꾼다. 이 항은 변 위에서
크기가 같고 방향이 반대인 한 쌍이라 운동량 · 각운동량은 지키지만, 굽힘 에너지에 없는 변 늘이기 · 줄이기 힘이다
(θ = 0 · ±90° 에서 0, ±45° 에서 최대). 따라서 **원문 가정을 힘(기울기)까지 쓰면 틀린 힘이 생긴다.**
노멀만 고정하고 `ê` 를 정확히 두면 기울기는 정확하다 — Hessian 오차와 비용은 아직 재지 않았다.

**P2 원 논문이 버린 감쇠 비대칭 항** `∇C (∇²C v)ᵀ` 는 `∂d/∂x` 의 중앙 72 % · 최대 136 % 다. 표본 속도는
꼭짓점마다 독립 난수라 실제 궤적과 다르다. 다만 유도로 보면 강체 회전에서는 `Ċ = 0` 이라 원 논문이 남긴 항
`Ċ∇²C` 가 0 이 되고 버린 항만 남는다(아직 재지 않음). 실제 시뮬레이션 궤적에서 다시 잴 것.

**P5 시간** (단일 스레드, 모으기 포함, 힌지당, 다른 작업 없이 두 번 잰 범위): 정확판 `Eval` 1.92 – 2.09 µs,
길이 고정판 0.22 µs, 힘 · Jacobian 조립까지 2.23 – 2.41 / 0.58 – 0.59 µs. 정확판이 약 9 배 느리고, 힌지 118,405 개면
한 단계 0.23 – 0.25 초다(Mathematica 가 함께 돌 때는 길이 고정판이 0.26 – 0.56 µs 로 흔들렸다). `results/*.json` 은
마지막 실행 값이다. 원인은 정확 Hessian 을 좌표에 대해 통째로 펼친 것이다.
