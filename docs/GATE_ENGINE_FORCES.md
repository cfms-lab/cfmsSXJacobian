# 엔진의 나머지 힘 — 손 코드 대 생성기의 유도

상태: **끝 (2026-11-14) — 닿는 힘 다섯을 견줬다.** 봉제 스프링 · 비선형 막 법칙(인장 · Provot 전단) · 꼭짓점 테더는 엔진 손 코드가
생성기의 유도와 반올림까지 같다. **전단 접선 다항식은 힘은 같지만 J 가 틀린다**(노드쌍 블록의 방향 — 삼각형의 꼭짓점 번호가 커지는
순서일 때만 맞는다). 견주다가 하나 더 나왔다: **패널별 재질이 막 힘에 먹지 않는다**(메시 전체가 노드 0 의 재질을 쓴다).
둘 다 기본 경로가 아닌 선택지다. 나머지 힘은 닿는 길이 없어 읽기만 했다. 비교하는 동안 엔진 리포는 읽기만 했다.
**그 뒤 사용자 요청으로 전단 접선 다항식의 J 를 엔진 브랜치 `sxjacobian-link` 에서 고쳤다 — 수정 판정 PASS**(맨 아래 「수정」; 엔진 브랜치
커밋 3a35c64 — 사용자 요청으로 엔진 main 에 합쳐 push 했다).
**패널별 재질도 사용자 요청으로 엔진 브랜치에서 고쳤다 — 수정 판정 PASS**(맨 아래 「수정 2」; 엔진 커밋 441b685 — 사용자 요청으로
엔진 main 에 합쳐 push 했다, 엔진 main = 원격 = 441b685).
사용자 요청 「엔진의 나머지 힘들도 비교해 줘」. 기준 표를 따로 확인받지는 않았다 — 이 문서에 먼저 적고 돌렸다. 하네스를 준비하면서
탐침으로 이미 본 값이 있었다(아래 「정식 실행 전에 알고 있던 것」).

## 무엇을 보이나

지금까지 엔진 cfmsDrape 의 손 코드와 견준 것은 굽힘 둘(Macri · Bridson/Oh)과 기본 인장 · Provot 전단이다
(`docs/GATE_ENGINE.md` · `GATE_BRIDSON.md` · `GATE_LINK_L0.md` · `GATE_LINK_L3.md`). 여기서는 **엔진의 나머지 힘**을 훑는다.

1. 엔진에 어떤 힘이 더 있는지 목록을 만든다(378d20c 를 읽기만).
2. 닿는 것마다 같은 모형을 조건 함수 한 줄로 쓰고, 생성기가 유도한 `C · ∇C · ∇²C` 로 만든 힘 · J 를 엔진의 값과 견준다.
3. 엔진의 J 가 엔진 힘의 미분인지를 엔진 힘의 유한차분으로 따로 본다.

정확도 기준은 여전히 유한차분이다(엔진 손 코드는 기준이 아니다). 명세의 유도 식은 명세마다 유한차분으로 확인한다 —
새 명세 다섯은 Mathematica 게이트를 거치지 않았다.

## 방법

- 엔진: 기준 378d20c 를 리포 밖에서 빌드한 CPU DLL(`%TEMP%\cfmsDrape_build_378d20c`, L0 과 같은 빌드)의 **사본**을 쓴다 —
  다른 세션이 그 빌드 폴더를 다시 링크해도 서로 막지 않게 하려는 것이다. 엔진 소스 · 워크트리는 읽기만 한다.
- 엔진 값: 디버그 고리로 힘 `f(X)` 와 `J·e`(단위 벡터마다)를 잰다. `J_fd` 는 `f` 의 중심차분이다(간격 1e-4 cm, 분모 = 실제 간격).
  힘이 여럿 섞이는 경우는 켠 것에서 끈 것을 빼 그 힘의 몫만 본다(힘 · J 는 더해진다).
- 생성기 쪽: 명세의 `condition()` 을 생성기의 `derive`(평탄 정확판)에 넣어 `C · ∇C · ∇²C` 를 유도하고 Python 에서 수치 평가한다
  (`tests/engine_forces.py`). **생성 C++ 을 부르지 않는다** — 명세마다 C++ 기준 도구를 짓지 않으려는 것이다. 그래서 이 문서가
  보는 것은 「생성기의 유도」이지 「출력한 C++」이 아니다.
  - 힘 `f = −k Σ C ∇C`, 감쇠 `d = −kd Σ Ċ ∇C`.
  - J 의 판: GN `−k Σ ∇C∇Cᵀ`, 정확판 `GN − k Σ C ∇²C`, C > 0 판 `GN − k Σ max(C, 0) ∇²C`.
- 테더는 디버그 고리에 안 잡혀 한 단계 적분으로 본다: 내부 힘 · 감쇠 · 공기 저항을 모두 0 으로 두면 테더 노드는 저마다 대각 계이고,
  식 (6) 은 `Δv = [h(−k(x − t) − c v) − h² k v] / (m + h c + h² k)` 다.

## 기준 (정식 실행 전 고정)

이 문서는 통과 · 미달을 가리는 게이트가 아니라 **비교 기록**이다. 낱말의 뜻만 미리 고정한다.

| 낱말 | 뜻 |
|---|---|
| 힘이 **같다** | `max|f_엔진 − f_명세| / max|f_명세|` ≤ 1e-10 (L0 의 문턱) |
| J 가 어느 판과 **같다** | 그 판과의 상대 오차 ≤ 1e-10. 세 판 모두 넘으면 「어느 판과도 다르다」 — 가장 가까운 판과 그 오차를 적는다 |
| J 가 **제 힘의 미분이다** | `max|J − J_fd| / max|J_fd|` ≤ 1e-6 |
| 한 단계 뒤 속도가 **같다** | 상대 오차 ≤ 1e-9 (L3 의 한 단계 문턱) |

- **전제 H0**: 하네스가 이미 아는 경우를 다시 낸다 — 엔진 기본 인장의 힘이 인장 명세와 같고 J 가 C > 0 판과 같다(L0).

## 정식 실행 전에 알고 있던 것

하네스와 명세를 짜면서 리포 밖 임시 폴더에서 같은 엔진 DLL 을 찔러 봤다. 그래서 아래는 정식 실행 전에 이미 안다.

- 봉제: 힘이 `k(x₁ − x₀)`, k = 1e6 (= 10 E), J 가 `∓k I` 블록, 제 힘의 유한차분과 9e-12.
- 비선형 인장: 힘 4e-16, J 가 C > 0 판과 5e-16 — 매개변수 다섯 조합 모두.
- 비선형 전단: 변형률을 `|w_u ± w_v|/b − 1` 로, κ 를 `k_hard / E` 로 둘 때만 힘 8e-16 · J 가 C > 0 판과 4e-16. 다른 두 가설은 0.08 – 0.3 어긋났다.
- 전단 다항식: 힘 4e-16 – 6e-16. **J 는 격자에서 정확판과 0.22 – 0.32 어긋나고 제 힘의 유한차분과도 그만큼 어긋났다.** 삼각형 하나로
  꼭짓점 순서 여섯을 돌리니 번호가 커지는 순서 (0, 1, 2) 에서만 3.9e-16 으로 맞고, 나머지는 번호가 뒤집힌 노드쌍의 블록이 전치돼 있었다.
- 테더: 한 단계 뒤 속도 · 위치가 닫힌 식과 1.8e-16. (인장 · 전단 · 굽힘의 점성 V · SV · BV 까지 0 으로 둬야 한다 — E = 0 이어도
  점성 힘은 남는다. 설정 뒤 첫 단계는 준비 단계라 한 번 먼저 밟는다.)
- 패널별 재질: 패널 1 의 E 를 바꿔도 막 힘이 그대로이고, 패널 0 의 E 를 바꾸면 메시 전체가 그 값으로 바뀌었다.
- 생성기는 새 명세 다섯에서 모든 변형을 낸다(1 노드 · 2 노드 스텐실, `Piecewise`, `asin` 포함). 생성 C++ 을 컴파일하지는 않았다.

곧 정식 실행은 이 값들을 한 하네스에서 고정한 장면으로 다시 내 기록하는 일이다.

- **봉제**: 엔진의 봉제 스프링은 벡터 조건 `C = x₁ − x₀` 다. 길이 0 스프링이라 힘이 `k(x₁ − x₀)`, J 가 `∓k I` 이고 제 힘의 미분과 같다.
  감쇠도 `kd(v₁ − v₀)`(등방)라 벡터 조건의 감쇠와 같다 — 스칼라 조건 `|x₁ − x₀|` 로 쓰면 변 방향 성분만 남아 엔진과 달라진다.
  `k = E · 10 · 가중`, `kd = 2 V · 10 · 가중` 이다(10 = `GlobalSewingFactor`).
- **비선형 막 법칙**: `½kC²` 가 아니라 구간마다 다른 `W(ε)` 지만, `½k g(ε)² = W(ε)` 가 되게 `g` 를 잡은 조건 한 줄(`Piecewise`)로 옮겨진다.
  그 조건의 C > 0 판이 엔진의 J 와 반올림까지 같다 — 엔진의 처방(접선 강성 + 늘어난 성분의 기하 강성만)이 바로 이 판이다.
  전단 성분은 변형률이 `|w_u ± w_v|/b − 1`, 굳음 계수가 `k_hard · SE / E` 다.
- **꼭짓점 테더**: 벡터 조건 `C = x − target` 이고, 식 (6) 의 한 단계가 엔진과 반올림까지 같다. 엔진은 이 힘을 노드쌍 블록이 아니라
  계의 대각에 넣는다.

### 엔진에서 나온 것 둘 (기본 경로 아님)

**① 전단 접선 다항식의 J — 노드쌍 블록의 방향.** 힘은 명세와 같다(곧 에너지는 맞다). 그런데 J 는 삼각형의 꼭짓점 번호가 요소 안에서

쌍은 블록이 전치돼 있다.** 이 커널의 3 × 3 블록은 대칭이 아니라서(그래서 설정 함수가 전치 처리 곱을 켠다) 슬롯에 넣을 때 행 노드 ·

- 디버그 곱은 풀이가 쓰는 것과 같은 곱(`_Jacobian_VectorProduct`, 전치 처리 플래그 전달)이다. 풀이 경로 자체를 따로 재지는 않았다.

## 읽기만 한 것 (재지 않았다 — 확인이 필요한 읽기다)

엔진 378d20c 의 소스를 읽어 정리한 것이다. 숫자로 확인하지 않았고, 「보인다」로 적은 것은 읽은 사람의 해석이다.

- **감쇠 D2 · D3**(기본 켜짐): 메시의 변과 땀마다. D2 는 `−Kd(v₀ − v₁)` 꼴인데 천의 변에서는 힘을 쓰지 않고 속도 Jacobian `Kd I` 만
  넣는다(힘은 Kang 인장 형식일 때만). D3 는 `−Kd x̂x̂ᵀ(v₀ − v₁)` 과 `Kd x̂x̂ᵀ`. `Kd = InternalDamping × GlobalDampingFactor`(기본 0.1).
  조건 함수로는 k = 0 인 감쇠만의 항이다. 시간 간격을 반으로 줄여 다시 풀 때 Kd 가 한 번 더 더해지는 것으로 보인다.
- **공기 저항**(기본 켜짐, 5 s⁻¹): `f = −c (v·n) n`, `c = 율 × 질량`, 법선 n 은 현재 모양의 꼭짓점 법선. 대각에 `h c n nᵀ`. 법선의 위치 미분은 없다.

  힘이 없다. 쉬는 길이를 다른 변에서 재는 것으로 보인다. 전용 API 가 없어 목록이 빈다.
