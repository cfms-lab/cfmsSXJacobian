# 엔진 연결 L3 (인장 · 전단) — 엔진 안에서 생성 인장 · Provot 전단이 엔진 손 코드와 같은 값을 낸다

상태: **PASS (2026-11-13)** — 엔진 브랜치 `sxjacobian-link` 349543e(로컬만)의 생성 인장 · Provot 전단 커널이 엔진 손 커널과 힘 · J 5e-16 이하, 한 단계 뒤 속도 5e-14 안이고, 끄면 엔진 main 과 비트까지 같다. 아래 「판정 기준」은 실행 전에 고정했고(사용자가 이 기준으로 진행을 정했다) 바꾸지 않았다. 판정 뒤 사용자 결정으로 기본을 `on` 으로 바꾸고 엔진 main 에 합쳐 push 했다(엔진 92d8838 — 끝의 「판정 뒤」 절). 계획은 `docs/PLAN_ENGINE_LINK.md` 의 L3 줄이다.

## 왜

L2 는 굽힘을 엔진 안에 넣었다. L3 는 남은 두 힘 — 인장과 전단 — 을 넣는다. 굽힘과 다른 점이 있다. 굽힘은 엔진 손 코드(Oh)의
Jacobian 이 근사라서 생성 GN 이 **다른 값**을 냈고, 그래서 적분 판정(L4 · L4R)이 따로 필요했다. 인장 · 전단은 엔진 손 코드가
이미 맞는 모형이다. 그래서 L3 의 목표는 **같은 값**이다 — 손으로 짠 커널을 명세에서 생성한 커널로 바꿔도 엔진이 같은 수를
내는 것. 같은 값이면 켜도 엔진의 동작이 바뀌지 않으므로 인장 · 전단에는 L4 꼴의 적분 판정이 필요 없다.

준비는 끝났다.

- 인장 명세는 엔진과 같은 모형이다(L0: 속도 0 에서 힘 · J 4e-16).
- Provot 전단 명세는 게이트를 통과했다(`docs/GATE_PROVOT_SHEAR.md`, GO). 엔진 꼴과 같은 힘이다(V1b).
- 엔진 손 코드의 J 처방 — 성분마다 `C > 0` 일 때 `−k C∇²C`, `Ċ > 0` 일 때 `−kd Ċ∇²C` — 을 그대로 내는 엔진 꼴 변형
  `EvalEngineTensionRate` 를 생성기에 더했다(사용자 결정 2026-11-13, `docs/GATE_LINK_L1.md` L1-5, PASS).

## 엔진 갈래 (브랜치 `sxjacobian-link`, 켤 때만 돈다)

- 새 파일 `SDECore_SXJMembrane.cpp` 에 인장 · 전단 커널을 둔다. 생성 헤더 `BaraffStretch_Engine.h` · `ProvotShear_Engine.h` 의
  사본(`sxgen/`, 바이트 그대로)에서 `EvalEngineTensionRate` 를 부른다.
- 스위치: 환경 변수 `CFMS_CPU_SXJ_MEMBRANE` = `off`(기본) · `on`. 굽힘 스위치와 따로다. 기본을 바꿀지는 L3 뒤에 사용자가 정한다.
- 인자: x = 엔진 위치 × `DimensionFactor`, 속도 = 엔진 속도, uv = 쉬는 2D 패턴, 인장 `prm = {E, V}`, 전단 `prm = {SE × GSF, SV × GSF}`,
  대각선 길이 = 엔진의 `b_su` · `b_sv` 그대로.
- 엔진 커널이 하던 다른 일(변형률 저장 · 최대 변형률 · 늘림 한계 시험 · 스테이지 · 힘 칸의 `=` / `+=`)은 그대로 한다.
- 다루지 않는 경우는 엔진 손 커널로 물러선다: 비선형 재질, 전단 다항식, upper · serial 이 아닌 조립, 기본이 아닌 J 플래그,
  기본이 아닌 인장 · 전단 형식. 가드에 걸리는 요소(α ≤ 1e-8, 길이 ≤ 1e-12)는 그 요소만 손 커널에 맡긴다.
- 엔진 main · 원격은 그대로 둔다.

## 장면

L0 · L2 와 같은 작은 천(노드 25)과 탐침 상태 X, 재질 넷(stretch · shear · bend · all). 여기에 **속도가 있는 탐침**을 더한다 —
무작위 속도(시드 고정, 크기 ±20 cm/s)를 `set_velocities` 로 준다. 굽힘은 `CFMS_CPU_SXJ_BEND=off` 로 끄고 잰다(인장 · 전단만 본다).
`all` 재질에서는 굽힘 기본(`gn_state`)을 켠 조합도 잰다.

규칙을 이렇게 정한 이유:

- **1e-12**: 같은 모형의 두 구현이라 반올림 순서만 다르다. L0 가 엔진 인장과 이 리포 명세를 4e-16 으로 봤다. 1e-12 는 L2 와 같은 문턱이다.
- **속도 탐침**: 엔진 처방의 `Ċ > 0` 몫은 속도가 있어야 나타난다. 속도 0 만 재면 `EvalEngineTension` 과 `EvalEngineTensionRate` 를 가릴 수 없다.
- **L3-4**: V 블록의 곱을 꺼내는 고리가 없다. 20 회 고정 PCG 는 반복 수가 정해져 있어(끝난 까닭이 반올림에 흔들리지 않는다) 한 단계
  뒤의 차이가 블록의 반올림 차이만 반영한다. 문턱 1e-9 는 그 차이가 PCG 20 회에서 불어나는 여유를 준 것이다.
- **적분 궤적을 판정하지 않는 것**: 수렴 PCG 는 끝나는 반복이 반올림에 따라 하나 달라질 수 있고, 그러면 궤적이 문턱(1e-6) 크기로
  갈린다. 같은 값인지는 L3-2 – L3-4 가 본다. 궤적 차이는 보고만 한다.

## 측정 메모 (구현하면서 정한 것 — 기준은 그대로)

판정 실행 전에 하네스를 짜면서 정했다. 기준 표의 문턱 · 조합은 바꾸지 않았다.

  그래서 쉬는 평면 천에서 한 단계를 먼저 밟고(아무것도 움직이지 않는다 — 위치 차이 0, 속도 0) `set_positions(X)` ·

  PCG 20 회 · 끝난 까닭 `iteration_cap`」 인지도 함께 본다(아니면 L3-4 미달로 친다).
- **L3-1 은 기준보다 더 본다.** 기준의 네 재질 f · J · 무작위 곱 · L2 의 매단 천 40 단계에 더해, 속도 탐침의 f · J · 곱, L3-4 의
