# 엔진 연결 L0 — 엔진 규약 확인 (cfmsDrape CPU 378d20c, 소스는 고치지 않음)

판정 기준은 실행 전에 고정한다(볼트 규칙 §1, 2026-11-13). 계획은 `docs/PLAN_ENGINE_LINK.md` 의 L0 이다.
**결과(2026-11-13): L0-0 – L0-4 모두 PASS.**

- 엔진 인장의 힘과 `J` 가 이 리포 인장 명세의 힘 · `EvalImplicitTension` 강성(`k = E`)과 반올림 수준(4e-16)으로 같다.
  모형 · 계수 · 단위 · `C > 0` 처방이 모두 같다는 뜻이다.
- 엔진 곱 연산은 선형이고, 스레드 수(32 대 1)와 무관하게 비트까지 같다.
- 보고: 엔진의 네 `J` 는 정확히 대칭이다. 굽힘 힘은 Bridson 힘과 3e-16 으로 같다. 굽힘 `J` 는 GN 과도 99 % 다르다.

아래 「결과」.

## 왜

생성 코드를 엔진에 붙이기 전에, 엔진이 **실제로** 쓰는 힘 · Jacobian 이 소스를 읽어 짐작한 규약대로인지 엔진 DLL 로 잰다.
L1(`docs/GATE_LINK_L1.md`)은 그 규약을 이 리포에서 흉내 낸다. L0 은 진짜 엔진에서 같은 것을 확인한다.

- 부호 · 단위 · 계수 대응: `J = ∂f/∂x`, CGS, 인장 `k = E`.
- 엔진 인장이 이 리포 인장 명세와 같은 모형 · 같은 처방(`C > 0` 일 때만 `C∇²C`)인가.
- 엔진 곱 연산이 선형이고 결정적인가.

엔진 리포는 읽기만 한다. 빌드는 리포 밖(`%TEMP%`)에 하고, 엔진의 디버그 고리 두 개만 부른다.

- `cfms_debug_internal_force(pos)` — 위치 `pos` 에서 엔진이 조립한 내력. 중력 · 외력은 끈다.
- `cfms_debug_stiffness_product(pos, r)` — 같은 위치에서 엔진이 조립한 `J` 로 `J r` 을 낸다(`SDEVC.cpp:1269-1323`).
  `V` 는 이 고리로 볼 수 없다.

## 장면 (실행 전에 고정)

- **쉬는 모양.** 평평한 정사각 격자 4 × 4 칸, 간격 2 cm. 노드 25, 삼각형 32(반시계, 엔진 화이트박스 시험
  `scripts/py_whitebox_fd_test.py` 의 `_patch` 와 같은 분할), 안쪽 변 = 힌지 40. 쉬는 uv = 쉬는 위치의 (x, y), 단위 cm. θ0 = 0.
- **잴 상태 X.** 쉬는 위치 `(x, y, 0)` 을 다음으로 옮긴다.
  - `x' = 1.08 x + 0.10 y`, `y' = 0.03 x + 0.94 y`, `z' = 0.6 sin(πx/8) sin(πy/8)`.
  - 각 성분에 균등 잡음 ±0.15 cm 를 더한다(`numpy.random.default_rng(20261113)`).
  - 늘어난 성분과 눌린 성분이 함께 생기고, 힌지가 접힌다.
- **속도.** 새로 만든 엔진의 속도는 0 이다. 그래서 감쇠 몫(`d` · `Ċ∇²C`)은 0 이다.
- **재질** — 엔진 화이트박스 시험처럼 재질 값으로 힘을 하나씩 떼어 낸다. 모두 `mass = 0.1`, 중력 0, `dt = 0.005` 다.

  | 이름 | E | SE | BE_U |
  |---|---|---|---|
  | 인장 | 1e5 | 0 | 0 |
  | 전단 | 0 | 1e5 | 0 |
  | 굽힘 | 0 | 0 | 1 |
  | 모두 | 1e5 | 1e5 | 1 |

- **재는 것.** 재질마다 네 가지를 잰다.
  - `f(X)`.
  - 단위 벡터 75 개로 곱해 되살린 전역 `J`(75 × 75).
  - 무작위 벡터 5 개(같은 시드)의 곱 `P(r)`.
  - 보고용으로 `f` 의 중앙 유한차분. 간격은 1e-4 cm, 분모는 실제로 표현된 간격 `xp − xm` 이다.
- **이 리포의 기준.** 평탄판 `Eval` 의 C · ∇C · ∇²C 로 요소 행렬을 만들어 전역으로 모은다. 요소별 C · ∇C · ∇²C 는 작은 도구
  `tests/link_l0_ref.cpp` 가 내고, 조립은 Python 이 한다.
  - 인장 명세(`BaraffStretch`)는 `k = E` 로 둔다. 기준 힘은 `f = −k Σ C ∇C`, 기준 J 는 `J_T = −k Σ (∇C∇Cᵀ + C⁺ ∇²C)` 다.
  - 굽힘 보고용 Bridson 명세(`BridsonBend`)는 `k = BE_U` 로 두고, `w̄` 를 엔진처럼 그 상태의 값
    `3 L0² / (½|nA| + ½|nB|)`(L0 = 쉬는 변 길이)로 준다. 힌지의 꼭짓점 순서는 `MakeGrid` 와 같은 `(h, i, j, k)` 다.

## 명제 — 기준은 실행 전에 고정

| 명제 | 내용 | 기준 |
|---|---|---|
| L0-0 전제 | DLL 의 `build_info()` 가 git_commit 378d20c · dirty = false 다. 실행 뒤 엔진 리포 `git status --porcelain` 이 비어 있다(엔진 리포에 아무것도 쓰지 않았다) | 둘 다 그렇다 |
| L0-1 곱의 일관성 | 재질 넷마다 되살린 `J` 로 곱한 `J r` 과 엔진 곱 `P(r)` 의 차이를 무작위 벡터 5 개에서 잰다. 척도는 `P(r)` 의 최대 크기다. 엔진 곱이 선형이고, 단위 벡터로 되살린 행렬이 엔진이 쓰는 행렬이라는 뜻이다 | 1e-12 이하 |
| L0-2 인장 힘 | 인장 재질의 `f(X)` 대 이 리포 기준 `−k Σ C ∇C`(`k = E`). 척도는 기준 힘의 최대 크기다 | 1e-10 이하 |
| L0-3 인장 J | 인장 재질의 `J` 대 이 리포 `J_T`(`k = E`). 척도는 `J_T` 의 최대 크기다. 장면의 인장 성분 64 개 중 C > 0 과 C ≤ 0 이 각각 10 개 이상이어야 갈래가 둘 다 시험된다 | 1e-10 이하 · 갈래 각 10 개 이상 |
| L0-4 결정성 | (i) 한 프로세스 안에서 같은 호출을 두 번 하면 `f` 와 `P(r)` 이 비트까지 같다(재질 넷). (ii) `OMP_NUM_THREADS = 1` 프로세스와 기본 스레드 프로세스의 `f` · `J` 가 비트까지 같다(재질 넷) | 모두 같음 |

L0-2 · L0-3 의 1e-10 은 반올림(1e-15 안팎)보다 다섯 자리 위다. 엔진과 이 리포는 같은 식을 다른 순서로 계산한다 — 엔진은
`k = E/a`, `C = a(|w| − 1)` 이고, 이 리포는 `C = √a (|w| − 1)` 이다. 계수 · 단위 · 모형 · 처방이 하나라도 다르면 차이는 장면의
변형률(수 %)만큼 난다. 그래서 1e-10 으로 둘을 가를 수 있다.

보고(판정 밖):

- 재질마다 `J` 의 비대칭 `max|J − Jᵀ| / max|J|` 와, 유한차분과의 차이 `max|J − J_FD| / max|J_FD|`(엔진 Jacobian 이 그 힘의 미분과
  얼마나 다른가).
- 인장: 엔진 `J` 대 이 리포 정확판 `−k Σ (∇C∇Cᵀ + C ∇²C)`. 눌린 성분에서 버린 몫의 크기다.
- 굽힘: 엔진 `f` 대 이 리포 Bridson 힘(`w̄` = 그 상태의 값). 엔진 `J` 대 이 리포 GN `−k Σ ∇C∇Cᵀ`(같은 `w̄`).
- 전단(Provot): `J` 대 유한차분, 비대칭. 이 리포에는 아직 Provot 명세가 없다(L3 전에 만든다).
- 기본 스레드 수(`cfms_openmp_threads`)와 DLL 의 SHA-256.

| 인장 | 0 | 0.102 | 2.19e5 | 3.83e4 |

- **인장.** 엔진 `J` 대 이 리포 정확판은 0.102 다. 이것은 눌린 성분(C ≤ 0)에서 엔진이 버린 `C∇²C` 몫이다. 정확판 대
  유한차분은 2.4e-9 다 — 유한차분이 그 정도로 맞는다는 뜻이다. 엔진 `J` 대 유한차분 0.102 는 정확판과의 차이와 같은 몫이다.
- **굽힘.** 엔진 힘 대 이 리포 Bridson 힘(w̄ = 그 상태 값)은 3.4e-16 이다. Bridson 게이트 B6 이 엔진 밖 하네스에서 본 것을
  엔진 DLL 에서 다시 확인했다.
  - 엔진 `J` 는 이 리포 GN 과 0.99, 정확판(w̄ 고정)과 1.05 만큼 다르다. Bridson 게이트 B7 의 「어느 쪽도 아님」과 같다.
  - 이 리포 정확판(w̄ 고정)과 유한차분의 차이 0.049 는 엔진 힘이 w 를 지금 넓이로 다시 재는 몫이다(`f∇wᵀ/w`, Bridson 게이트).
- **비대칭 0.** 전치 처리 플래그가 꺼진 기본에서는 `J_ij = J_ji = B` 다. 그래서 전역 `J` 는 노드쌍 슬롯의 블록 B 가 모두 대칭일
  때만 대칭이다. 엔진의 기존 인장 · Provot 전단 · Bridson 굽힘은 이 장면에서 슬롯 블록이 모두 대칭 3 × 3 이다.
  - 이 리포의 굽힘 · Baraff–Witkin 전단 블록은 비대칭이다(L1 보고). 그래서 엔진 갈래는 플래그를 켜야 한다.
- **결정성의 범위.** 장면이 노드 25 개라 작다. 큰 메시의 스레드 분할은 L6 에서 다시 본다.

## 빌드 · 실행

- 빌드: `tests\build_engine_dll.bat`. `CFMS_DRAPE_DIR`(없으면 `..\cfmsDrape_dev`)의 `drape` 를 리포 밖
  `%TEMP%\cfmsDrape_build_<커밋>` 에 CMake(VS 2022, x64, Release)로 빌드한다. 대상은 `cfmsDrape` 하나뿐이다.
  - 엔진 CMake 의 `cfms_deploy` 대상(공유 `cfmsShared2026_dev/predist` 로 복사)은 따로 부를 때만 돈다. 그래서 이 빌드는
    리포 밖 `%TEMP%` 에만 쓴다. 빌드 메타데이터는 엔진의 git 상태를 읽기만 한다.
- 실행: `python tests\link_l0.py <DLL> <link_l0_ref.exe>`. 엔진의 Python 포장(`cfmsdrape`)은 엔진 리포에서 읽어 들인다.
  바이트코드를 쓰지 않는다(`sys.dont_write_bytecode`). 결과는 `results/gate_link_l0.json` 에 쓴다.

## 이 게이트가 보이지 않는 것

- `V`(`∂f/∂v`) — 디버그 고리로 볼 수 없다. 소스로 읽은 것만 있다(인장 `V = −kv Σ∇C∇Cᵀ`, `SDECore.cpp:9652`). 엔진 갈래(L2)에서
  고리를 더해 잴지 정한다.
- 전치 처리 플래그가 켜졌을 때의 곱 — 기본(꺼짐)만 잰다. 켜는 길(굽힘 감쇠 암시 모드 · 전단 다항식)은 다른 항도 함께 바꾼다.
  비대칭 블록의 곱은 L1-3 이 이 리포에서 흉내 낸 것으로 본다.
- 속도가 0 이 아닌 상태, 고정점 · 접촉 · 봉제, 패널마다 다른 재질.
