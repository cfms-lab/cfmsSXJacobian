## 목적

지금까지의 게이트는 이 리포 안의 하네스(작은 천 · 노드 441)에서만 돌았다. 생성 코드가 **실제 엔진의 시간 적분 · 충돌 ·
의복 장면** 안에서도 (1) 같은 값을 내고, (2) 깨지지 않으며, (3) 엔진 손 코드보다 나쁘지 않은 시간에 도는지를 본다.
대상은 cfmsDrape CPU 엔진의 요소 힘 · Jacobian(인장 · 전단 · 굽힘)이다. 충돌 · 접촉 · 봉제 · 공기 저항 · 변 감쇠는
건드리지 않는다.

## 그대로 꽂히지 않는 것 — 어댑터가 할 일

1. **출력 꼴.** 이 리포의 `EvalImplicit*` 는 `A_e = h·∂(f+d)/∂v + h²·∂f/∂x` 와 `b_e` 를 낸다. 엔진은 **`J` · `V` 를 따로, 그리고
   이웃 노드쌍 블록만** 받는다(대각은 행 합 규약). → 생성기에 엔진용 변형을 하나 더 낸다: `f + d`, 노드쌍 `J` 블록
   (삼각형 3 · 힌지 6), 노드쌍 `V` 블록. 강성 판(정확 · GN · T)은 지금과 같은 계수 바꾸기로 고른다. 이 리포의 조건은 모두
   병진 불변이라 행 합 규약이 정확하다(요소 하나에서 `Σ_n ∂²C/∂x_m∂x_n = 0`) — 첫 판정에서 잰다.
   → **L1 에서 했다**: `EvalEngine` · `EvalEngineGN` · `EvalEngineTension`(`generated/<이름>_Engine.h`). 행 합 복원이 `A_e` · `b_e` 와
   반올림 수준으로 맞는다.
2. **블록 방향.** 엔진 슬롯은 (작은 번호, 큰 번호)이다. 생성 블록은 힌지 · 삼각형 지역 순서라 노드 번호가 뒤집히면 전치해
   넣어야 하고, 전치 처리 플래그를 켜야 한다. → L1-3 에서 이 규칙(뒤집히면 `J_abᵀ`, 플래그 켬)으로 흉내 낸 엔진 곱이 맞음을 봤다.
3. **꼭짓점 순서 셋.** 힌지는 `_vid`, Oh 커널의 `nn`, 이 리포 명세의 `(h, i, j, k)` 가 서로 다르다(Bridson 게이트에서 대응을 이미
   읽어 확인했다). 삼각형은 엔진 `ppElements` 순서와 명세 순서.
4. **모으기.** 엔진 배열(`_R` · `_V` 3N 섞인 배치, 굽힘은 `ppNodes`)에서 바로 모은다. SXMesh 를 엔진에 들이는 것은 이 계획 밖이다
   (아래 「결정할 것」 ④).
5. **계수 · 단위.** 인장 `k = E`(엔진의 `E/α` 와 이 리포 `√a` 곱이 같은 에너지 — 첫 판정에서 잰다), 감쇠 `kd = V`, 굽힘 `k = BE_U`,
   CGS 그대로.
6. **결정성.** 새 커널도 요소 소유 슬롯 + 요소 순서 환원으로 쓴다. 엔진 기본 경로의 회귀 해시는 바뀌면 안 된다(새 경로는
   켤 때만 돈다).

## 결정할 것 (사용자)

1. **엔진 리포를 고쳐도 되는가 — 결정: 별도 브랜치에서 된다(사용자, 2026-11-13).** `cfmsDrape_dev` 에 브랜치 · 워크트리
   `sxjacobian-link`(main 378d20c 에서 분기)를 두고, 새 힘 형식(`SDEitfGenerated` 등)을 **켤 때만** 도는 갈래로 넣는다.
   기본값 · main 은 그대로 둔다. 생성 헤더는 이 리포 `generated/` 에서 복사하고 해시를 맞춘다(SXMesh 사본과 같은 방식).
   엔진 main 에 합치거나 엔진 원격에 push 하는 것은 요청이 있을 때만이다.
2. **CPU 엔진부터인가, GPU 엔진부터인가 — 결정: CPU 먼저(사용자, 2026-11-13).** 기본 출하 경로이고, 굽힘 · 인장 모형이 이 리포 명세와 같으며, Bridson
   게이트의 하네스 경험이 그대로 쓰인다. GPU 는 행렬 꼴은 더 가깝지만 힘 모형이 달라 비교 기준부터 새로 세워야 한다.
3. **전단 모형 — 결정: Provot 명세를 새로 쓴다(사용자, 2026-11-13).** 엔진 기본(Provot 대각선 늘림)과 이 리포 명세(Baraff–Witkin `w_u·w_v`)가 다르다. 권고 = **엔진 모형을 명세로
   하나 더 쓴다**(`C± = √a(|w_u ± w_v| − √2)` — 조건 함수 한 줄, 인장처럼 볼록이라 `IMPLICIT_TENSION` 판도 낼 수 있다).
   모형을 바꾸지 않고 손 코드만 바꾸므로 의복 결과를 견줄 수 있다. Baraff–Witkin 전단으로 바꾸는 것은 재질 보정이 따르는
   모형 변경이라 따로 정한다.
4. **SXMesh 를 엔진에 들이는가 — 결정: 이번에는 들이지 않는다(사용자, 2026-11-13).** 엔진 배열에서 바로 모으는 어댑터로 값과 안정을 먼저
   본다. SoA 자동 생성의 이득은 엔진 쪽 모으기 비용을 잰 뒤 따로 정한다.

## 위험

- **PCG 반복 20 회 고정**이 기본이라 강성 판을 바꾸면 결과가 바뀐다(**L4 에서 바로잡음**: C API 기본은 수렴하는 풀이다 — 위 「선형계」 줄. L4 는 두 모드를 모두 잰다). 이 리포 적분 게이트는 수렴할 때까지 풀었다. L4 에서 두
  모드를 모두 재야 판단이 선다.
- **엔진 처방과의 차이.** 인장은 엔진이 감쇠 기하 강성을 `Ċ > 0` 일 때 남기고 T 판은 버린다. 비선형 재질 갈래도 있다. 이
  차이를 L3 판정문에서 먼저 정한다.
- **굽힘 가중치.** 엔진은 w 를 매 단계 **지금 넓이**로 잰다(Bridson 게이트). 명세는 쉬는 값 w̄ 다. 엔진의 θ0 항 계수 2 도
  있다(`2 sin(θ0/2)`, θ0 = 0 이면 무관). 의복 결과가 이 차이로 갈릴 수 있다.
- **h 를 반으로 줄여 다시 푸는 갈래에서 V 블록이 두 번 더해질 수 있다**(조사 보고 · 미검증). 엔진 기존 문제라면 엔진 쪽 결정이다.
- **노드 0 재질만 읽는 인장 · 전단**(보고 · 미검증) — 의복 장면에서 패널마다 재질이 다르면 손 코드와 생성 갈래가 함께 틀린다.
- 엔진 회귀 해시: 새 갈래는 켤 때만 돌아야 하고, 기본 경로의 `final.npy` 해시가 그대로인지 매번 확인한다.

## 하지 않는 것

엔진 main · 기본값 변경, 충돌 · 접촉 코드, GPU 엔진(결정 ② 가 바뀌지 않는 한), SXMesh 엔진 도입(결정 ④), 엔진 손 코드의
버그 수정(찾으면 보고만 — 고칠지는 사용자 몫).
